# Как устроен фронтенд Хабитона

Основа соответствует учебному проекту: функциональные компоненты, отдельные страницы, маршруты и CSS Modules. Новые средства добавлены для состояния, сохранения и PWA. Tailwind, Redux и TypeScript не используются.

## Порядок изучения

1. `src/main.jsx` — React запускается в элементе `root`, подключаются CSS и `HashRouter`.
2. `src/App.jsx` — приложение оборачивается в общий провайдер данных.
3. `src/routing/Routing.jsx` — каждому адресу назначается компонент страницы.
4. `src/components/Layout/Layout.jsx` — оболочка и навигация вокруг страницы.
5. `src/pages/TodayPage.jsx` — пример экрана с данными и действиями.
6. `src/context/AppContext.jsx` — общие данные и их изменение.

## Структура

```text
src/
  components/
    UI/          кнопки, поля, карточки, диалоги
    Layout/      оболочка и навигация
    HabitCard/   карточка одной привычки
    Calendar/    календарь и переключение месяцев
  pages/         компоненты страниц
  routing/       адреса и маршрутизация
  context/       общие данные приложения
  hooks/         сохранение в браузере и состояние PWA
  data/          исходные демонстрационные данные
  utils/         даты, расписания, пути ресурсов
```

Небольшие связанные страницы сгруппированы: `ProfilePages.jsx` содержит профиль, настройки и напоминания. Каждый экран при этом остаётся отдельным компонентом.

## Компоненты и пропсы

`HabitCard` получает данные, но сама не выбирает расписание:

```jsx
<HabitCard habit={habit} done={true} onToggle={() => toggleLog(habit.id)} />
```

`habit` — объект привычки, `done` — выполненное состояние, `onToggle` — функция родительской страницы. Если обработчик не передан, карточка показывает переход к деталям. Её можно использовать в списке, сегодняшнем плане и календаре.

## useState

Хранит изменяемые данные одного экрана: текст формы, выбранную вкладку, открытый диалог. В редакторе объект `draft` содержит поля, а `errors` — ошибки. `value` показывает текущее значение, `onChange` обновляет его. После изменения React заново вычисляет отображение компонента.

## Context

`AppProvider` хранит данные, которые нужны нескольким страницам. Хук `useApp()` возвращает эти данные и функции изменения.

В `data` находятся:

- `profile` — имя и демонстрационный email;
- `habits` — привычки и периоды расписания;
- `logs` — отметки с `habitId` и датой;
- `dialogues` — сообщения, предложенные планы и состояние сохранения;
- `users`, `templates`, `audit` — данные демонстрационной админки.

Отдельно сохраняются настройки темы и часового пояса. `session` обозначает только роль демонстрационного просмотра. В настоящем приложении авторизацию и права должен проверять Laravel.

## Путь одного действия

При нажатии чекбокса:

1. `TodayPage` получает привычки и отметки из `useApp()`.
2. `scheduled()` выбирает запланированные на дату привычки.
3. Страница передаёт объект и обработчик в `HabitCard`.
4. Чекбокс вызывает `toggleLog(id)`.
5. Провайдер добавляет отметку либо удаляет существующую пару «привычка + дата».
6. React обновляет список, счётчик и сад.
7. `useLocalStorage` сохраняет новый объект в браузере.

Для связи с Laravel сохранение позднее будет заменено запросом к API и подтверждением результата сервером.

## useEffect и localStorage

`useEffect` выполняет действия вне расчёта JSX: подписку на состояние сети, смену темы, таймеры, сохранение данных. При уходе с компонента обработчики и таймеры удаляются.

`useLocalStorage` читает сохранённые значения при запуске и записывает их изменения. Если браузер запретил хранение или место закончилось, интерфейс продолжает работать в памяти. Сохранение между запусками в этом случае не гарантируется. Пароль в хранилище не записывается.

## Маршрутизация

На GitHub Pages используется `HashRouter`: экран привычек имеет адрес `https://account.github.io/habiton/#/habits`. Всё после `#` обрабатывает React, поэтому статическому серверу не нужны правила для каждой страницы.

- `Routes` и `Route` выбирают страницу.
- `Link` меняет адрес без полной перезагрузки.
- `Outlet` показывает дочернюю страницу внутри оболочки.
- `useNavigate` выполняет переход после сохранения.
- `useParams` получает ID из адреса `/habits/:id`.

Для проверки фронтенда маршруты сейчас доступны напрямую. Отдельного служебного экрана входа в демонстрацию нет. Настоящая проверка сессии и ролей будет подключена вместе с Laravel.

## CSS Modules и темы

`index.css` содержит базовые правила и CSS-переменные из UI kit. Тема меняет значения этих переменных через `data-theme` у `html`. Компоненты используют `var(--canvas)`, `var(--brand)` и другие общие значения.

Файлы `.module.css` изолируют имена классов. `Pages.module.css` содержит общие стили страниц. От 768 px навигация становится боковой; на широком десктопе привычки и сад стоят рядом. На телефоне административные таблицы превращаются в карточки записей.

## Даты и расчёты

`utils/dates.js` не зависит от React. В нём находятся отдельные проверяемые функции.

Расписание — массив периодов с `from`, `to`, `days` и `time`. При изменении предыдущий период закрывается, а новый начинается сегодня. При архивировании период закрывается; восстановление открывает новый. Дни недели: 0 — понедельник, 6 — воскресенье.

Статистика сравнивает выполненные действия с запланированными. Будущие дни не считаются пропущенными. Дата определяется выбранным часовым поясом и периодически пересчитывается, если приложение долго открыто.

## Помощник

Внешняя модель не подключена. `OnboardingPage` создаёт цель, `CoachPage` сохраняет сообщения и показывает подготовленные ответы. `makePlan` создаёт демонстрационные предложения. На `PlanPage` можно снять выбор и изменить предложение. Привычки появляются только после сохранения плана.

Короткий таймер имитирует ожидание и удаляется при уходе с экрана. При подключении ИИ его заменит запрос к серверу; ключ поставщика в браузер попадать не должен.

## PWA

- `public/manifest.webmanifest` — имя, иконки, стартовый адрес и режим отдельного окна.
- `public/icons/` — PNG и отдельная иконка Apple.
- `public/sw.js` — шаблон service worker.
- `scripts/build-pwa.js` — добавляет в worker точные адреса файлов после сборки Vite.
- `usePwa` — вспомогательный хук состояния PWA; сейчас не выводится в интерфейс.

Worker предварительно кеширует файлы приложения. Без сети навигация получает сохранённую оболочку. API не кешируется. Обновлённый worker активируется после закрытия предыдущих окон приложения, чтобы не сменить версию во время заполнения формы.

## Следующий этап с Laravel

UI и CSS можно сохранить. Потребуется заменить операции в провайдере на модуль запросов, добавить загрузку и ошибки, серверную cookie-сессию и CSRF-защиту, проверку прав и принадлежности данных. Диалог должен обращаться к серверному сервису ИИ. Базу MySQL и контракт API ещё предстоит реализовать.
