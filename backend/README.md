# Сервер Хабитона

PHP 8.1+ с `pdo_mysql`, `mbstring`, `curl` и MySQL 8. Без Composer и Laravel.

1. Запустите MySQL в MAMP и импортируйте `schema.sql` через phpMyAdmin.
2. Скопируйте `config.example.php` в `config.php`. Проверьте порт и данные MySQL.
3. Из корня репозитория запустите PHP:

   ```sh
   /Applications/MAMP/bin/php/php8.4.17/bin/php -S 127.0.0.1:8081 -t backend/public
   ```

4. Во втором терминале запустите React:

   ```sh
   cd frontend
   VITE_USE_BACKEND=true npm run dev
   ```

Открывайте адрес Vite. Он перенаправляет запросы `/api/` на PHP, а браузер работает с одним адресом. Вход и регистрация создают PHP-сессию. Данные из демонстрационной версии автоматически не импортируются.

## Qwen

Заполните `qwen_url` (полный HTTPS-адрес `…/chat/completions` для вашего региона), `qwen_key` и при необходимости `qwen_model` в локальном `config.php`. Для Alibaba Cloud Model Studio берите адрес из [официальной документации](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions). Модель должна поддерживать JSON-режим. Не добавляйте файл с ключом в Git. Без ключа интерфейс работает, но запрос помощника возвращает сообщение о настройке.

## Администратор

Зарегистрируйте свою учётную запись, затем назначьте ей роль в MySQL:

```sql
UPDATE habiton.users SET role = 'admin', name = 'Алексей'
WHERE email = 'ваша-почта@example.com';
```

При следующем запросе сервер заново прочитает роль. Обычная регистрация не выдаёт права администратора.

## Как устроен код

- `public/index.php` — точка входа, получает действие, проверяет сессию и возвращает JSON.
- `classes` — подключение PDO, чтение запроса, проверка полей, вызов Qwen.
- `models` — запросы к MySQL. Привычки, отметки и диалоги отбираются по идентификатору текущего пользователя.
- `controllers` — вход, регистрация и сценарий помощника.
- `schema.sql` — таблицы. Расписания, сообщения и пункты плана хранятся в JSON-полях. У отметки составной ключ из пользователя, привычки и даты, поэтому повторная отметка не создаёт дубль.

## Публикация

GitHub Pages продолжает показывать автономную демонстрацию. Для серверной версии соберите React с `VITE_USE_BACKEND=true npm run build` и разместите содержимое `frontend/dist` в корне HTTPS-сайта. Настройте сервер так, чтобы `/api/` запускал `backend/public/index.php`. Из папки бэкенда напрямую доступна только `public`, файлы конфигурации и схема находятся вне публичного каталога. Не включайте CORS для API: в текущей схеме фронтенд и API открываются с одного адреса.

Service Worker не кеширует API. В серверной версии после офлайн-перезапуска личные данные недоступны: они не сохраняются в браузере. В открытой до отключения вкладке уже загруженные данные остаются видимыми.
